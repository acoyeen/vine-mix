# VineMix website hosting

Published 27 October 2026 at **https://vinemix.app/** using Cloudflare Workers
Static Assets. Worker name: `vinemix-website`. No Worker script, application
server or database is required. The browser runs the existing animations.

## Publish an update

The initial deployment was a direct upload through the Cloudflare dashboard.
Automatic deployment from Git is **not configured**. Local edits alone do not
change the public website.

The authenticated Cloudflare plugin is also a verified publishing route as of
28 October 2026; browser sign-in and a separate Wrangler login are unnecessary
when its account tools are available. Use the direct asset-upload API flow:
register the full public-file manifest, upload the requested buckets using the
short-lived upload-session token, then deploy the assets-only Worker with the
completion token. Pass `_headers` contents in `assets.config._headers` rather
than exposing that file as an asset. Preserve existing routing, compatibility
and Worker settings. Keep tokens and temporary upload files outside the source
checkout and never include them in documentation or public assets. Verify all
public bytes and response headers after deployment. This does not enable Git
auto-deployment or authorize publishing development desktop releases.

1. In `website-redesign`, run `npm run build` and `npm run check`.
2. Preserve the complete `dist/assets/` directory: these assets are maintained
   separately and are not regenerated by the build.
3. Review the output for private files and accidental diagnostics. Upload only
   the contents of `dist/`, with `index.html` at the archive root. Do not upload
   the repository, local review screenshots, scripts or recovery backups.
4. In Cloudflare Workers & Pages, open `vinemix-website`, choose **New deployment**,
   and upload the prepared static files. Keep assets at `/`, HTML handling at
   `auto-trailing-slash`, and not-found handling at `none`.
5. Verify the live site, downloads, mobile layout and redirects after publishing.
   Keep the prior deployment version available for rollback.

`wrangler.jsonc` records the equivalent assets and primary-domain configuration
for a future authenticated Wrangler deployment. It contains no credentials.
The two zone redirect rules below are configured separately in Cloudflare.
Before enabling Git builds, commit the complete website source and required
assets, and use `website-redesign` as the build root. Do not change repository
visibility as part of hosting configuration.

## Domains and redirects

- `vinemix.app`: Worker custom domain, with Cloudflare-managed DNS and HTTPS.
- `www.vinemix.app`: proxied CNAME to `vinemix.app`.
- `vinemix.dev` and `www.vinemix.dev`: proxied CNAMEs to `vinemix.app`; the redirect
  rule handles the request before it reaches an origin.

The `vinemix.app` zone has the enabled Single Redirect named
**Canonical VineMix HTTPS address**, matching:

```text
(http.host eq "www.vinemix.app") or (http.host eq "vinemix.app" and not ssl)
```

The `vinemix.dev` zone has the enabled Single Redirect named
**Redirect VineMix dev to app**, matching:

```text
http.host in {"vinemix.dev" "www.vinemix.dev"}
```

Both use status **301**, preserve the query string, and use this dynamic target:

```text
concat("https://vinemix.app", http.request.uri.path)
```

Do not add an ordinary apex CNAME alongside the Worker-managed `vinemix.app`
record. A CNAME alone does not perform a browser redirect.

## Public output

`src/_headers` preserves content-type and referrer protections and prevents
framing. `src/robots.txt`, `src/sitemap.xml`, and the homepage canonical/OG URL
identify `https://vinemix.app/` as the public address. The build copies these
files into `dist/`. Cloudflare interprets `_headers` rather than serving it.
Installers, release notes and checksums remain on GitHub Releases.
